Changelog
=========

2026-08-29 (v10.0.0)
Nouvelles fonctionnalités : palette de commandes, extension de l'onglet médias, catalogue de la place de marché des extensions, améliorations d'accessibilité

- **Palette de commandes / recherche d'actions** : un nouveau raccourci
  (Cmd+Maj+J sous macOS, Ctrl+Maj+J sous Windows/Linux) ouvre une liste
  consultable de toutes les actions de l'application (éléments de menu,
  fonctions des onglets) — Entrée exécute l'action sélectionnée. Réduit
  le besoin de mémoriser l'ordre des onglets et les raccourcis clavier,
  implémenté sur les deux plateformes (Qt et wx).
- **Onglet médias** : les stations de radio peuvent désormais être
  enregistrées comme favorites (persistant), les flux yt-dlp affichent
  une navigation par chapitres avec saut lorsque des métadonnées de
  chapitres sont disponibles, et des effets en direct (compresseur/
  limiteur via la bibliothèque Pedalboard) peuvent être appliqués à la
  lecture de fichiers locaux. Les effets en direct ne sont possibles que
  pour les fichiers locaux pour des raisons liées au SDK, pas pour les
  flux radio web/YouTube/podcast.
- **Place de marché des extensions** : le navigateur d'extensions intégré
  pointait auparavant vers une URL de remplacement sans contenu. Il existe
  désormais un vrai catalogue hébergé dans le dépôt
  (docs/plugin_catalog.json) ainsi qu'une nouvelle extension de
  démonstration (une annonce de bienvenue à la connexion).
- **Accessibilité** : nouveaux contrôles `AccessibleSpinCtrl` et
  `CustomTextEntryDialog` (macOS/wx) inspirés de m45wxcontrols — lus plus
  fiablement par VoiceOver que `wx.SpinCtrlDouble`. Déjà appliqués au
  positionnement des utilisateurs (X/Y/Z) dans la zone d'administration.
- Correctif : le « surveillant d'utilisateurs » (surveillance à l'échelle
  du serveur de noms d'utilisateur spécifiques avec annonce à l'arrivée,
  depuis la v6.5.0) ne fonctionnait que sous macOS — la boîte de dialogue
  de gestion existait aussi sous Windows/Linux, mais n'était jamais reliée
  à l'événement d'arrivée. Désormais actif sur les deux plateformes.
- Plus de 550 nouvelles entrées/corrections dans les dictionnaires FR/ES
  dans le cadre de ce changement (couverture de traduction complète
  vérifiée).
- ROADMAP.md et SERVER_PLAN.md documentent la suite de la feuille de route
  (synchronisation d'appareils sur le réseau local, audio spatial, et un
  serveur compatible TeamTalk maison — ce dernier en attente d'une
  réponse de BearWare.dk concernant la licence).

2026-08-27 (v9.2.0)
Nouveau : prise en charge multilingue complète (DE/EN/FR/ES) pour l'UI, le manuel et le changelog

- src/i18n.py : ajout de toutes les entrées FR/ES manquantes du
  dictionnaire (plus de 550 nouvelles traductions). Correctif :
  lorsqu'une entrée FR/ES manquait, _lookup_direct() se rabattait
  silencieusement sur l'anglais au lieu de la langue cible – des mots
  anglais apparaissaient donc parfois au milieu de l'interface française
  ou espagnole. Cela concernait notamment de nombreux libellés dans
  ui_wx/tabs/settings.py, audio.py, media.py qui n'avaient jusqu'ici aucune
  entrée dans le dictionnaire (même pas en anglais).
- src/ui_qt/tabs/admin.py, channels.py, chat.py, speak.py : tous les
  textes de statut, d'erreur et de dialogue jusqu'ici codés en dur en
  allemand (gestion des comptes et de la liste de bannissement, menu
  contextuel des canaux, actions expulser/bannir/opérateur, export du
  chat, statut du streaming ElevenLabs, et plus) passent désormais par
  l'infrastructure de traduction – auparavant, ces textes restaient
  toujours en allemand quelle que soit la langue sélectionnée.
- Le manuel et le changelog sont désormais entièrement disponibles en
  anglais, français et espagnol dans des fichiers dédiés
  (manual_en/fr/es.html, CHANGELOG_en/fr/es.txt). Windows/Linux (Qt)
  affichent automatiquement le fichier correspondant à la langue de
  l'application ; macOS (wx) lit désormais aussi le fichier de changelog
  correspondant au lieu de l'ancienne substitution ligne par ligne, qui ne
  correspondait presque jamais sur du texte libre. Correctif : l'ancienne
  boîte de dialogue de changelog sur macOS affichait par erreur
  l'intégralité du changelog en allemand aux utilisateurs anglophones
  (branche « en » manquante).
- Le manuel macOS (texte intégré dans app_wx.py, indépendant de
  manual.html) reste volontairement une source séparée et n'a pas été
  modifié.

2026-08-27 (v9.1.1)
Correctif : Apple Foundation Models rendait le client inutilisable sous macOS 26

- src/apple_fm.py : le paquet applefoundationmodels actuel nécessite désormais
  macOS 27 (Golden Gate) – l'import natif du .dylib plantait durement sous
  macOS 26 (Tahoe) et versions antérieures (erreur dyld au lieu d'une
  exception Python interceptable, code de sortie 1). La nouvelle vérification
  _min_macos_ok() lit la version du système via platform.mac_ver() et empêche
  TOUT accès à applefoundationmodels en dessous de macOS 27 – ni
  is_available() ni generate() ne démarrent alors le sous-processus worker.
  Les fonctions concernées (résumé de chat, suggestions de réponse,
  classification d'intention, amélioration de texte, traduction en temps
  réel) basculent immédiatement et silencieusement sous macOS 26 sur
  Claude/Gemini/Ollama/extraction ; le client lui-même reste pleinement
  utilisable.

2026-07-26 (v9.0.0)
Nouvelle fonctionnalité : streaming Spotify via librespot + streaming Deezer via yt-dlp

Spotify :
- Nouveau mode de streaming « Spotify » dans l'onglet Média (Spotify Premium
  requis)
- Intégration via librespot : TeamTalk apparaît comme un appareil Spotify
  Connect dans l'application Spotify ; nom de l'appareil personnalisable
- Connexion web unique via OAuth (PKCE) : le navigateur s'ouvre
  automatiquement, librespot enregistre les identifiants pour tous les
  démarrages suivants
- Choix de qualité : 320 / 160 / 96 kbps
- Binaire librespot inclus (third_party/librespot/), installable aussi
  manuellement via python scripts/download_librespot.py
- Nouveaux fichiers : src/spotify_auth.py, src/spotify_streamer.py

Deezer :
- Nouveau mode de streaming « Deezer » dans l'onglet Média
- Authentification via jeton ARL (cookie de 192 caractères depuis
  deezer.com) ; la connexion par identifiant/mot de passe a été désactivée
  par Deezer
- Recherche via l'API publique gratuite de Deezer (aucun compte nécessaire
  pour rechercher)
- Téléchargement et déchiffrement via yt-dlp (déjà inclus, aucun nouveau
  paquet pip nécessaire)
- Le jeton est enregistré localement (~/.config/tt-vo-client/deezer_arl.txt)
- Nouveau fichier : src/deezer_downloader.py

CI / Build :
- build-macos.yml (nouveau) : build macOS via GitHub Actions, produit un DMG
- build-windows.yml + build-linux.yml : build de librespot avec Rust + cache
- Toutes les plateformes intègrent librespot automatiquement dans le bundle
  PyInstaller

2026-07-19 (v8.1.3)
Correction : détection de version cassée dans tous les scripts de build locaux + installateur Linux

- scripts/build_macos.sh, build_linux.sh, build_windows.ps1/.py : les quatre
  lisaient APP_VERSION depuis src/app.py – elle n'y est jamais définie
  (seulement le routeur de plateforme). Chaque script aurait échoué
  immédiatement à la lecture de la version. Lit désormais correctement
  depuis app_wx.py (macOS) ou app_qt.py (Windows/Linux).
- scripts/build_linux.sh : PKG_NAME avait « linux_x64 » codé en dur,
  indépendamment de l'architecture réelle de la machine de build – sur une
  machine Linux arm64, l'archive aurait été mal étiquetée. Lit désormais
  uname -m (x86_64/arm64), conformément à la convention de nommage CI.
- scripts/install_linux.sh (nouveau) : installe une version Linux
  compilée (depuis GitHub ou une archive .tar.gz locale), crée une entrée
  de menu + commande de démarrage et vérifie/installe les dépendances
  d'exécution manquantes (Debian/Ubuntu via apt). Détecte une
  incompatibilité d'architecture pour les archives locales et propose le
  téléchargement automatique de la version correspondante depuis GitHub.
- scripts/README.md : les téléchargements du SDK TeamTalk étaient
  documentés comme .zip (en réalité .7z), le nom de fichier du SDK Linux
  n'existait pas ainsi sur bearware.dk, libgtk-3-dev/GStreamer retiré des
  prérequis Linux (nécessaire seulement pour wx, que Linux n'utilise pas),
  indicateurs de script erronés corrigés dans la section anglaise.

2026-07-19 (v8.1.1)
Correctif : Apple Foundation Models ne fonctionnait pas du tout dans l'application compilée

- TeamTalk VO Client.spec : error_codes.json (un fichier de données
  d'applefoundationmodels) manquait dans le bundle – seul le .dylib était
  copié, mais le paquet charge en plus un fichier JSON avec les
  définitions de codes d'erreur lors de l'import. Sans lui, l'import
  échouait avec FileNotFoundError et Apple FM était en permanence
  « indisponible » dans chaque application compilée (indépendamment de
  la version de macOS) – silencieusement, sans message d'erreur, avec
  repli sur Claude/Gemini/Ollama/extraction.
- src/apple_fm.py : generate() s'exécute désormais dans un sous-processus
  isolé (l'application/le script se relance avec --apple-fm-worker).
  Protège contre les plantages natifs du framework Foundation Models
  (par ex. sur des versions de macOS pas encore entièrement prises en
  charge, comme Tahoe) – seul le worker plante, l'application reste en
  vie et le prochain backend de repli prend le relais.
- src/ai_summary.py : summarize_missed() écrasait inconditionnellement un
  résultat Apple FM déjà réussi par Claude dès qu'une clé API Claude était
  configurée (vérification « summary is None » manquante) – Apple FM
  n'était donc jamais utilisé si une clé Claude était aussi définie.

2026-06-16 (v8.0.5)
Correctif : VoiceOver lit correctement la liste des serveurs sous macOS 27 (deuxième tentative)

- src/ui/a11y.py : _cell_text() entièrement révisé – quatre stratégies
  dans l'ordre :
  1. Interroger directement la source de données
     (tableView_objectValueForTableColumn_row_) – indépendant du système
     AX, récupère le texte exactement tel qu'il est dans le modèle
     wx.ListBox.
  2. preparedCellAtColumn_row_ + stringValue – directement depuis la
     cellule.
  3. Protocole formel NSAccessibility (accessibilityChildren +
     Value/Label/Title).
  4. accessibilityAttributeValue_ historique + stringValue de sous-vue
     comme derniers recours.
- NSTableRowView (tableau basé sur des vues, macOS 10.7+) est désormais
  également corrigé en plus de NSTableRow – wxPython utilise sous macOS
  actuel des tableaux basés sur des vues, ce qui explique pourquoi les
  correctifs précédents ciblaient le mauvais type.

2026-06-16 (v8.0.4)
Correctif : VoiceOver lit à nouveau correctement la liste des serveurs sous macOS 27 (Golden Gate)

- src/ui/a11y.py : _cell_text() dans patch_list_row_accessibility()
  utilise désormais une stratégie en deux étapes : d'abord le protocole
  formel NSAccessibility (accessibilityChildren() /
  accessibilityValue()), puis un repli via la hiérarchie des sous-vues
  (stringValue). Sous macOS 27, accessibilityChildren() peut renvoyer un
  résultat vide sur un NSTableRow si Apple a restructuré la hiérarchie de
  vues interne de NSTableView ; le repli garantit la lisibilité.
- Catégorie NSTableRow : accessibilityTitle() ajouté – macOS 27 peut
  préférer cet attribut à accessibilityLabel() pour les entrées de liste.

2026-05-29 (v8.0.1)
Correctif i18n : VoiceOver parle désormais la bonne langue système (FR/ES/EN)

- Détection de la langue macOS corrigée : detect_system_language()
  utilise désormais NSLocale.preferredLanguages (PyObjC) au lieu de
  locale.getlocale(). Dans les bundles .app, locale.getlocale() renvoie
  toujours (None,None) ou 'en_US' – l'API macOS est la seule source
  fiable pour la langue d'interface réelle de l'utilisateur.
- Localisation du bundle corrigée : le .spec crée désormais des
  répertoires de/en/fr/es.lproj avec InfoPlist.strings après le build.
  Sans ces stubs, macOS ignore CFBundleLocalizations et VoiceOver choisit
  toujours la voix anglaise.
- Descriptions de rôle allemandes redondantes supprimées : les
  surcharges accessibilityRoleDescription dans a11y.py utilisant des
  chaînes DE codées en dur (« Taste », « Regler », etc.) ont été
  retirées. VoiceOver localise lui-même correctement ces rôles en
  FR/ES/EN. Les surcharges accessibilityRole (AXButton, AXList, etc.)
  restent. Le correctif accessibilityValue pour NSStepper (valeur
  numérique) reste également.
- Signalé par @math65 (Issue #27). Reproductible sur macOS 15.5 /
  système FR.

2026-05-27 (v8.0.0)
Intégration SRAL : couche de sortie lecteur d'écran unifiée (voix + braille)

- Intégration de SRAL (Screen Reader Abstraction Library) comme nouvelle
  couche de sortie SR. API unifiée : sr_output.speak() /
  sr_output.braille() / sr_output.output(). Windows : SRAL (NVDA / JAWS /
  SAPI / Narrateur) + braille via BRLTTY. Linux : SRAL avec Speech
  Dispatcher + libbrlapi. macOS : utilise toujours
  NSAccessibilityPostNotificationWithUserInfo (meilleure qualité que
  SRAL/VoiceOver.mm, car une priorité est définie) ; braille
  automatiquement via VO.
- screen_reader.py (Windows tolk/NVDA/SAPI) reste un repli si SRAL.dll ne
  peut pas être chargé.
- sr_output.py est la nouvelle interface canonique pour la sortie SR dans
  tout le projet (app_wx.py et app_qt.py).
- SRAL : binaire universel (arm64 + x86_64) sous macOS, x64 sous Windows
  (CI). Basé sur SRAL v0.3 de m1maker (licence MIT).

    anciens SettingsStore / ServerStore – pleine rétrocompatibilité.
  * Multi-serveur natif (server_session.py) : ServerSession encapsule
    chacun un TeamTalkClient, ServerManager gère un nombre quelconque
    de sessions. Événements : active_server_changed,
    server_state_changed sur le bus. La session active contrôle
    l'interface principale ; changement via
    ServerManager.switch_to().

  * Sortie de plage braille (braille_output.py) : BrailleOutputManager
    avec trois niveaux de verbosité (compact / normal / détaillé).
    Raccourci pour faire défiler (hotkey_cycle_braille_verbosity).
    Suivi du focus avec annonces automatiques lors des changements de
    zone. strip_for_braille() retire les émojis et caractères
    spéciaux. format_channel_entry() / format_user_entry() /
    format_message() ajustent la sortie selon le niveau de verbosité.
  * Contrôle vocal (voice_control.py) : VoiceCommandManager avec un
    backend Whisper (openai-whisper + pyaudio, optionnel). Reconnaît
    les commandes : muet, parler, canal <Nom> (flou), statut, aide,

    gracieux si Whisper n'est pas installé. Activation via
    settings.voice_control_enabled.
