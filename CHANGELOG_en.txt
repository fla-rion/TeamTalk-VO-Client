2026-08-27 (v9.2.0)
New: Full multilingual support (DE/EN/FR/ES) for UI, manual, and changelog

- src/i18n.py: Filled in all previously missing FR/ES dictionary entries
  (over 550 new translations). Bugfix: when a FR/ES entry was missing,
  _lookup_direct() silently fell back to English instead of the actual
  target language – so occasional English words showed up in the middle
  of the French/Spanish UI. This affected, among others, many labels in
  ui_wx/tabs/settings.py, audio.py, media.py that previously had no
  dictionary entry at all (not even English).
- src/ui_qt/tabs/admin.py, channels.py, chat.py, speak.py: all previously
  hardcoded German status, error, and dialog texts (account and ban-list
  management, channel context menu, kick/ban/operator actions, chat
  export, ElevenLabs streaming status, and more) now go through the
  translation infrastructure – previously these stayed German regardless
  of the selected language.
- The manual and changelog are now fully available in English, French, and
  Spanish as dedicated files (manual_en/fr/es.html, CHANGELOG_en/fr/es.txt).
  Windows/Linux (Qt) automatically show the file matching the app language;
  macOS (wx) now also reads the matching changelog file instead of the
  previous line-by-line substitution, which almost never matched on prose
  text. Bugfix: the previous macOS changelog dialog accidentally showed
  English-speaking users the entire changelog in German (missing "en"
  branch).
- The macOS manual (text embedded in app_wx.py, independent of
  manual.html) intentionally remains a separate source and was not
  touched.

2026-08-27 (v9.1.1)
Bugfix: Apple Foundation Models made the client unusable on macOS 26

- src/apple_fm.py: The current applefoundationmodels package now requires
  macOS 27 (Golden Gate) – the native import of the .dylib crashed hard on
  macOS 26 (Tahoe) and older (dyld error instead of a catchable Python
  exception, exit code 1). New check _min_macos_ok() reads the system
  version via platform.mac_ver() and prevents ANY access to
  applefoundationmodels below macOS 27 – neither is_available() nor
  generate() start the worker subprocess in that case. Affected functions
  (chat summary, reply suggestions, intent classification, text
  improvement, real-time translation) fall back on macOS 26 immediately
  and silently to Claude/Gemini/Ollama/extraction; the client itself
  remains fully usable.

2026-07-19 (v8.1.3)
Fix: broken version detection in all local build scripts + Linux installer

- scripts/build_macos.sh, build_linux.sh, build_windows.ps1/.py: all four
  read APP_VERSION from src/app.py – it is never defined there (only the
  platform router). Every script would have aborted immediately when
  reading the version. Now reads correctly from app_wx.py (macOS) or
  app_qt.py (Windows/Linux).
- scripts/build_linux.sh: PKG_NAME had "linux_x64" hardcoded, regardless
  of the actual architecture of the building machine – on an arm64 Linux
  machine the archive would have been mislabeled. Now reads uname -m
  (x86_64/arm64), matching the CI naming convention.
- scripts/install_linux.sh (new): installs a finished Linux release
  (from GitHub or from a local .tar.gz), sets up a menu entry + start
  command, and checks/installs missing runtime dependencies
  (Debian/Ubuntu via apt). Detects an architecture mismatch in local
  archives and offers an automatic download of the matching version
  from GitHub.
- scripts/README.md: TeamTalk SDK downloads were documented as .zip
  (actually .7z), the Linux SDK filename did not exist as documented on
  bearware.dk, libgtk-3-dev/GStreamer removed as a Linux requirement
  (only needed for wx, which Linux doesn't use), incorrect script flags
  in the English section corrected.

2026-07-19 (v8.1.1)
Bugfix: Apple Foundation Models didn't work at all in the built .app

- TeamTalk VO Client.spec: error_codes.json (a data file from
  applefoundationmodels) was missing from the bundle – only the .dylib
  was copied, but the package also loads a JSON file with error code
  definitions on import. Without it, the import failed with
  FileNotFoundError and Apple FM was permanently "unavailable" in every
  built .app (regardless of macOS version) – silently, with no error
  message, falling back to Claude/Gemini/Ollama/extraction.
- src/apple_fm.py: generate() now runs in an isolated subprocess (the
  app/script relaunches itself with --apple-fm-worker). Protects against
  native crashes in the Foundation Models framework (e.g. on macOS
  versions not yet fully supported, such as Tahoe) – only the worker
  crashes, the app stays alive and the next backend fallback kicks in.
- src/ai_summary.py: summarize_missed() unconditionally overwrote an
  already-successful Apple FM result with Claude as soon as a Claude API
  key was configured (missing "summary is None" check) – Apple FM
  therefore never got used when a Claude key was also set.

New: Apple Foundation Models – on-device AI without an API key (macOS 26+, Apple Silicon)

  classification, text improvement, real-time translation.

  bundle.
- Requires: macOS 26+ (Tahoe) or macOS 27 (Golden Gate), Apple Silicon
  (M1+).

2026-06-16 (v8.0.5)
Bugfix: VoiceOver reads the server list correctly on macOS 27 (second attempt)

- src/ui/a11y.py: _cell_text() completely reworked – four strategies in
  order:
  1. Query the data source directly (tableView_objectValueForTableColumn_row_)
     – independent of the AX system, gets the text exactly as it is in the
     wx.ListBox model.
  2. preparedCellAtColumn_row_ + stringValue – directly from the cell.
  3. Formal NSAccessibility protocol (accessibilityChildren +
     Value/Label/Title).
  4. Legacy accessibilityAttributeValue_ + subview stringValue as last
     resorts.
- NSTableRowView (view-based table, macOS 10.7+) is now patched in
  addition to NSTableRow – wxPython uses view-based tables on current
  macOS, which is why the previous patches were addressing the wrong
  type.

2026-06-16 (v8.0.4)
Bugfix: VoiceOver reads the server list correctly again on macOS 27 (Golden Gate)

- src/ui/a11y.py: _cell_text() in patch_list_row_accessibility() now uses
  a two-stage strategy: first the formal NSAccessibility protocol
  (accessibilityChildren() / accessibilityValue()), then a fallback via
  the subview hierarchy (stringValue). On macOS 27, accessibilityChildren()
  can return empty on an NSTableRow if Apple has restructured the internal
  view hierarchy of NSTableView; the fallback ensures readability.
- NSTableRow category: accessibilityTitle() added – macOS 27 may prefer
  this attribute over accessibilityLabel() for list entries.

2026-06-09 (v8.0.3)
Compatibility: macOS 27 (Golden Gate) – legacy accessibility API removed

- src/ui/a11y.py: _cell_text() in patch_list_row_accessibility() now uses
  the formal NSAccessibility protocol (accessibilityChildren() /
  accessibilityValue()) instead of the accessibilityAttributeValue_
  method, deprecated since macOS 10.10. Apple is further deprecating the
  informal AX API in macOS 27; the new code is more robust and
  future-proof.
- NSTableRow category: accessibilityAttributeValue_ override removed
  (was redundant, since accessibilityLabel and accessibilityValue are
  already correctly patched via the formal protocol).
- All remaining accessibility patches (accessibilityRole,
  accessibilityLabel, etc.) via objc.Category remain unchanged and are
  compatible with macOS 27.

2026-05-29 (v8.0.1)
i18n bugfix: VoiceOver now speaks the correct system language (FR/ES/EN)

- Fixed macOS language detection: detect_system_language() now uses
  NSLocale.preferredLanguages (PyObjC) instead of locale.getlocale(). In
  .app bundles, locale.getlocale() always returns (None,None) or
  'en_US' – the macOS API is the only reliable source for the user's
  actual UI language.
- Fixed bundle localization: the .spec now creates de/en/fr/es.lproj
  directories with InfoPlist.strings after the build. Without these
  stubs, macOS ignores CFBundleLocalizations and VoiceOver always
  chooses the English voice.
- Removed redundant German role descriptions: accessibilityRoleDescription
  overrides in a11y.py that used hardcoded DE strings ("Taste", "Regler",
  etc.) were dropped. VoiceOver localizes these roles correctly on its
  own in FR/ES/EN. The accessibilityRole overrides (AXButton, AXList,
  etc.) remain. The accessibilityValue fix for NSStepper (numeric value)
  also remains.
- Reported by @math65 (Issue #27). Reproducible on macOS 15.5 / FR
  system.

2026-05-27 (v8.0.0)
SRAL integration: unified screen-reader output layer (speech + braille)

- Integrated SRAL (Screen Reader Abstraction Library) as the new SR
  output layer. Unified API: sr_output.speak() / sr_output.braille() /
  sr_output.output(). Windows: SRAL (NVDA / JAWS / SAPI / Narrator) +
  braille via BRLTTY. Linux: SRAL with Speech Dispatcher + libbrlapi.
  macOS: still uses NSAccessibilityPostNotificationWithUserInfo (higher
  quality than SRAL/VoiceOver.mm, since priority is set); braille
  automatically via VO.
- screen_reader.py (Windows tolk/NVDA/SAPI) remains as a fallback if
  SRAL.dll cannot be loaded.
- sr_output.py is the new canonical interface for SR output throughout
  the project (app_wx.py and app_qt.py).
- SRAL: universal binary (arm64 + x86_64) on macOS, x64 on Windows (CI).
  Based on SRAL v0.3 by m1maker (MIT license).

2026-03-28 (v2.0.0)
- Pillar 1 – architecture:
  * SQLite settings database (settings_db.py): all app settings and
    server profiles are now stored in a single SQLite file
    (settings.db). Automatic migration from JSON files on first
    launch. SQLiteSettingsStore / SQLiteServerStore have an identical
    API to the old SettingsStore / ServerStore – full backward
    compatibility.
  * Native multi-server (server_session.py): ServerSession wraps a
    single TeamTalkClient each, ServerManager manages any number of
    sessions. Events: active_server_changed, server_state_changed on
    the bus. The active session controls the main UI; switch via
    ServerManager.switch_to().
  * Plugin system: already fully implemented in v1.10.x.

  * Braille display output (braille_output.py): BrailleOutputManager

    to cycle through them (hotkey_cycle_braille_verbosity). Focus
    tracking with automatic announcements on area changes.
    strip_for_braille() removes emoji and special characters.
    format_channel_entry() / format_user_entry() / format_message()
    adjust the output per verbosity level.
  * Voice control (voice_control.py): VoiceCommandManager with a
    Whisper backend (openai-whisper + pyaudio, optional). Recognizes
    commands: mute, speak, channel <name> (fuzzy), status, help, quit.

    Whisper is not installed. Enabled via
    settings.voice_control_enabled.

  * Live transcription (transcription.py): TranscriptionManager buffers
    PCM audio and transcribes it every 5 seconds via Whisper. Result as

    missed messages. Backends: Claude API
